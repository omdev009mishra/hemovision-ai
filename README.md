## 1. Problem Statement

Anemia affects over **1.6 billion people worldwide** (approx. 25% of the global population), with the highest prevalence among young children, pregnant women, and individuals in resource-limited settings. Left unmanaged, severe anemia leads to maternal mortality, impaired cognitive development in children, and chronic fatigue/reduced productivity in adults.

The standard diagnostic gold standard for measuring hemoglobin (Hb) is invasive blood sampling—such as complete blood count (CBC) via automated hematology analyzers or point-of-care hemoglobinometers (e.g., HemoCue). However, invasive testing poses several barriers in remote or low-resource settings:
* Need for trained phlebotomists and micro-cuvettes/reagents.
* Biohazard risk associated with blood handling.
* Patient discomfort and reluctance toward frequent invasive capillary/venous punctures.

The **palpebral conjunctiva** (the interior lining of the lower eyelid) is rich in microvascular capillaries and light on melanin pigment, making its color and spectral reflectance directly sensitive to systemic hemoglobin concentrations. Advancements in smartphone optics, computer vision, and machine learning offer a compelling opportunity to explore non-invasive screening via consumer mobile devices.

---

## 2. Research Objective

The primary objective of HemoVision is to systematically investigate:

> **Whether smartphone images of the palpebral conjunctiva contain sufficient, stable, and reproducible visual information to reliably screen for anemia risk and estimate systemic hemoglobin levels under diverse population and environmental conditions.**

        ↓

        ↓

        ↓
Image Quality Assessment (Blur, Exposure, Occlusion)
        ↓
Conjunctiva Segmentation (ROI Extraction)
        ↓
Image Normalization (Color Calibration, Illumination Correction)
        ↓

        ↓
ML Model (Regression / Classification Baseline)
        ↓
Hb Estimation / Anemia Risk
        ↓
Uncertainty Assessment (Confidence Interval / Reliability Filter)
        ↓
User Result (Screening Category / Quality Alert)

## 6. Phase 0 Validation

The Phase 0 repository foundation has been hardened and validated against automated quality gates:
* **Draft 2020-12 JSON Schema Validation**: Strict verification of schema structure, required fields, properties, root object type, and Draft 2020-12 spec compliance using `Draft202012Validator`.
* **Synthetic Fixture Validation**: Automated testing of fictional synthetic samples (`dataset/samples/`) validating clean pass behavior.
* **Negative Schema Tests**: In-memory unit tests verifying that missing required fields, non-numeric values, or invalid enum categories are strictly rejected.
* **Automated Pytest Verification**: 100% passing rate across `ml/tests/test_schemas.py`.
* **GitHub Actions CI**: Continuous Integration workflow (`.github/workflows/ci.yml`) enforcing automated test execution on push and PR.
* **Repository Security Verification**: Strict verification confirming zero real patient records, medical images, API keys, or environment secrets in version control.
